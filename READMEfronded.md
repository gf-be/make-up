修改前端界面：删除倒溯处理模块

## 页面整体结构
本页面为通报数据的**导入核验工作台**，采用「左侧导航 + 右侧主内容区」的布局，覆盖**临时数据管理、人工核验、倒溯处理**三大核心流程，支持JSON文件导入、数据筛选、核验入库、回溯处理全链路操作。
##导入检查模块页面结构重构
新增左侧固定导航，把页面按「临时区 / 人工核验 / 倒溯处理」拆成三个独立视图

功能模块拆分：把现有导入检查模块页面里的功能，按业务阶段分到三个模块里。
临时区：只放 JSON 上传功能、临时区数据统计（比如待人工核验数|倒溯待处理数）、最近导入结果列表（将原字段"来源json"改为"来源用户名"）
人工核验：顶部 Tab 分为「飞行检查 / 抽检通告」。主区左右分栏：右侧保持现有通告详情与工作区不变；左侧为极简折叠筛选侧栏——「产品类别」「年度分布」两块默认展开，块标题左侧配图标、右侧为折叠箭头，点击下方缩进列表行（文案 + 浅蓝色数量）完成筛选；年号列表可纵向滚动。单个通告：通过使用「可导入」入库（逻辑同现状），不通过「打回」进入倒溯；展示字段「来源 JSON」改为「来源用户」；打回后在倒溯处理页关联展示批次（需后端：批次 id、与用户/临时区通告批次的级联）
倒溯处理：存放异常数据的修正、删除功能（需要在临时区完全删除，确保下次导入不报重复错误）、待处理列表（展示通告标题，打回时间等相关逻辑）




##核心交互逻辑
1.  **数据流转**：导入JSON → 临时区预览 → 人工核验 → 确认入库/标记异常 → 异常数据进入倒溯处理区修正
2.  **权限与状态控制**：不同模块的数据状态隔离（临时区/核验中/已入库/异常），避免误操作
